### 기획 의도

📌 왜 이 게임을 만들었는가 (2~3문장)
- 일반 FPS의 조준은 마우스 감도와 반응 속도의 싸움이다
- XR에서는 **실제로 총을 어떻게 잡고, 어떤 자세로 겨누는가**가 실력이 될 수 있다
- 그런데 트래킹 데이터는 클라이언트에서만 측정된다 → 이걸 서버 권위 구조에서 어떻게 신뢰할 것인가가 핵심 과제

### 2-1. 무기 핸들링: 조준 안정도

📌 GIF: 흔들릴 때 vs 안정적일 때 탄 퍼짐 비교 + 디버그 HUD 수치

- 서버가 최근 N프레임의 총구 흔들림을 직접 계산해 탄 퍼짐에 반영
- 클라이언트는 원본 트래킹만 전송하고, "안정도" 같은 판정 결과는 보내지 않음

### 2-2. 양손 파지

📌 GIF: 한 손 사격 vs 양손 파지 사격의 반동·흔들림 차이

- 보조 손이 총열 영역을 잡으면 서버가 양손 파지로 판정
- 파지 판정 → 흔들림 보정 → 조준 안정도 → 탄 퍼짐으로 이어지는 하나의 시스템

🔗 코드: 📌 링크
🔗 결정 기록: https://github.com/<GITHUB_ID>/XRFPS/blob/main/docs/decisions/ADR-0002-mvp-mechanics.md

### 2-3. 서버 권위 트래킹 동기화와 검증

📌 다이어그램: 클라이언트(트래킹 원본) → 서버(검증·계산) → 다른 클라이언트(복제)

- 손-HMD 거리 한계, 프레임 간 이동 속도, 전송 빈도 검증
- 명중 판정과 HP는 서버만 변경

### 원칙

- 진행 순서: 목표 정의 → 설계 논의 → 대안 비교 → **결정(개발자)** → 구현 → 리뷰 → 기록
