- 날짜 / 마일스톤: 2026-10-06 ~ 10-07 / M0
- 소요 시간: (직접 기입)

## 사용한 도구와 모델
| 작업 | 도구 | 모델 | 선택 이유 |
|---|---|---|---|
| 조사 설계, 결과 종합, 추천 | Claude Code | Claude Opus 5.5 | 상충하는 출처를 비교·판단해야 하는 작업 |
| 엔진·플러그인 조사 | Claude Code Workflow (에이전트 11개) | Opus 5.5 | 5개 관점 병렬 조사 → 관점별 독립 검증 → 완결성 비평 |
| PC 업그레이드 조사 | Claude Code Workflow (에이전트 8개) | Opus 5.5 | 4개 관점 병렬 조사 → 가격·사양 독립 검증 |

규모: 엔진 조사 약 37분·서브에이전트 토큰 약 166만, PC 조사 약 21분·약 96만.
→ 버전 호환성처럼 **틀리면 며칠을 잃는 결정**에만 이 비용을 쓰고, 일반 작업은 단일 대화로 진행한다.

## AI가 한 일 / 내가 한 일
- AI:
  - Epic·Meta 공식 문서 간 모순 5건 발견, 1차 출처로 해소 (Target SDK 34/35/36, NDK 25/r27c, JDK 17/21 등)
  - 함정 발견: VS 2026 기본 컴파일러(MSVC 14.51)로는 UE 5.8 빌드 실패
  - Meta XR Simulator가 AMD GPU 미지원·Listen Server 크래시 → Meta 플러그인 비추천 근거
  - PC에서 기존 VS 2022 + MSVC 14.44를 발견하고 VS 추천을 2026 → 2022로 수정
  - RAM 시세, 싱글→듀얼 채널 효과, 데스크톱 가격대, eGPU 대안 조사
- 나:
  - UE 5.8.3 선택, RAM 16GB 증설 결정, 새 PC는 보류
  - 최종 설치 구성 확정

## AI가 틀렸거나 고친 부분
- 첫 추천(VS 2026)은 PC 상태를 확인하기 전이었다. 실제 설치 상태를 본 뒤 VS 2022로 바뀜 → **환경 조사는 추천 전에 먼저 한다.**
- 검증 단계에서 조사 에이전트의 주장 일부가 반박됨
  - 예: "Shipping 크래시 이슈에 Meta 답변 없음" → 실제로는 Meta가 "재현 불가"라고 답함
  - 예: 다나와 기사에 없던 "하반기 15~20% 상승 전망" 수치가 붙어 있었음
- 사용 가능 기간("Quest 개발 3~4년")은 측정값이 아니라 추정임을 명시하도록 함

## 검증 방법
- 각 조사 결과를 별도 에이전트가 원문을 다시 열어 confirmed / refuted / outdated / unverified로 판정
- PC 상태는 시스템 명령어(vswhere, MSVC 폴더, 환경변수)로 직접 확인
- 설치 후 체크리스트의 확인 항목(java 버전, NDK 버전, 빌드 로그의 MSVC 버전)으로 최종 검증 예정
