# M1 설계 회의 (VR 템플릿 분석 → 구조 결정)

- 날짜 / 마일스톤: 2026-10-15 ~ 10-18 / M1 준비
- 소요 시간: (직접 기입)

## 사용한 도구와 모델
| 작업 | 도구 | 모델 | 선택 이유 |
|---|---|---|---|
| 템플릿 분석 지도, 설계 회의 진행, PR 리뷰 | Claude Code | Claude Opus 5.5 | 설계 판단과 교육적 설명이 중심인 작업 |
| PR 리뷰 코멘트 등록 | GitHub CLI (`gh api`) | — | 리뷰를 GitHub에 줄 단위로 남겨 이력이 보이게 |

## 진행 방식
- 2026-10-13부터 AI의 역할을 **"20년차 팀장 × 신입"** 으로 재설정
  - 신입(나)이 먼저 분석·제안하고 팀장(AI)이 리뷰
  - 개념 확인 질문 허용, M1부터 브랜치 + PR 리뷰 흐름
- 첫 PR(#1, VR 템플릿 분석)은 리뷰 3회 후 머지
- 리뷰 코멘트는 같은 GitHub 계정으로 등록되어 `[팀장 리뷰]` 접두사로 구분

## AI가 한 일 / 내가 한 일
- 나:
  - VR 템플릿 직접 분석 (컴포넌트 구성, 잡기 흐름, `Triggered` 핀 확인)
  - **핵심 게임 루프 정의**: "누가 더 빠르게 보조 손으로 자세를 잡느냐"
  - 결정: 총은 별도 Actor, C안 구조, 히트스캔, 위치만으로 양손 파지 진입, 히스테리시스 도입, 라운드 전 총 선택(파밍 없음), 무기 교체 백로그
  - Snap이 조준 실력을 없애지 않을지, 양손 판정을 총에 두면 동기화 문제가 없을지 먼저 의문 제기
- AI:
  - 블루프린트 읽는 법, Grip/Aim 포즈, Snap, 햅틱, MSAA, 언리얼 좌표계 등 개념 설명
  - 템플릿의 넘겨잡기 구조가 양손 파지와 충돌한다는 점을 질문으로 유도
  - 구조 대안(A/B/C), 입력 소스 대안 비교와 추천
  - 시간 부족으로 입력 프레임 구조(`FXRInputFrame`) 숙제는 AI가 대신 작성, 회의 결과 문서도 AI가 작성하고 내가 리뷰하는 방식으로 역할 교대

## AI가 틀렸거나 고친 부분
- **요구 오해**: E2(주 손이 총을 놓을 때) 논의에서 내가 "선택창 vs 파밍 중 고민"이라고 한 것을 AI가 "둘 다 있다"로 이해하고 파밍을 전제로 추천했다. 다시 설명해서 바로잡음
- **결정 근거 재확인**: 총을 Actor로 정한 근거 중 "떨어뜨림"이 사라지자, AI가 결정 자체를 다시 검토하고 남은 근거로 유지 판단 → ADR에 근거 변경까지 기록
- **환경 문제를 늦게 발견**: 2026-10-10 `cmd`를 찾지 못한 오류를 AI가 명령어 문제로 넘겼는데, 실제로는 시스템 PATH가 비어 있던 신호였다 ([트러블슈팅](../troubleshooting/2026-10-16-system-path-wiped.md))
- **설치 안내 오류**: gh 설치 후 "터미널을 새로 열면 된다"고 안내했지만, 앱 내장 터미널은 앱 시작 시점의 PATH를 물려받아 효과가 없었다

## 검증 방법
- 분석 문서는 PR 리뷰 3회로 검증 (사실/판단 분리, 렌더링 확인, 용어 정확성)
- 설계 결정은 대안 비교표와 함께 ADR-0004로 기록
