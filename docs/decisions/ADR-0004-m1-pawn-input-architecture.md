# ADR-0004: M1 플레이어 구조와 입력 소스 추상화

- 날짜: 2026-10-18
- 상태: 채택
- 결정자: 박세훈 (M1 설계 회의)
- 상세 설계: [03-m1-design.md](../design/03-m1-design.md)

## 배경

- VR 템플릿은 이동·잡기·메뉴를 Pawn 하나의 블루프린트에 모두 넣고, 왼손·오른손 상태를 `HeldComponentLeft` / `HeldComponentRight`처럼 쌍으로 관리한다. 그 결과 한 손이 바뀌면 다른 손 상태를 수동으로 맞추는 코드(넘겨잡기 참조 정리)가 필요했다. ([02. VR 템플릿 분석](../design/02-vr-template-analysis.md))
- 우리 게임은 기능이 계속 늘고 M2에서 네트워크가 붙는다. 양손 파지 판정은 무기마다 기준이 다르다.
- [ADR-0001](ADR-0001-dev-workflow.md)에서 Quest 입력과 데스크톱 시뮬레이션 입력을 갈아끼우는 구조를 약속했다.

## 결정 1: 플레이어 구조

### 검토한 대안

| | A. 기능별 (템플릿 방식) | B. 손 단위 | **C. 손 단위 + 총이 규칙** |
|---|---|---|---|
| 구성 | 기능 컴포넌트가 양손을 같이 처리 | 손 컴포넌트 ×2, 양손 판정은 Pawn | B + 양손 판정·사격은 총(Actor) |
| 장점 | 기능을 한 곳에서 봄 | 양손이 같은 코드, `PrimaryHand`가 손 하나를 가리킴 | 무기별 규칙이 무기 안에, 서버 재계산 구조가 명확 |
| 단점 | 왼손·오른손 변수 쌍이 계속 생김 | Pawn이 무기 규칙까지 알아야 함 | 클래스 수가 조금 많음 |

### 결정

**C안.** 손 컴포넌트 ×2 + Pose 컴포넌트 + 총(Actor)이 양손 판정과 사격을 담당한다.

### 이유

- "정보를 가장 잘 아는 쪽에 책임을 준다": 손 상태는 손에, 무기 규칙(총열 선, 허용 거리)은 무기에
- 양손 파지 판정이 "포즈 + 무기 데이터 → 결과"인 함수가 되어, 클라이언트(연출)와 서버(결과)가 같은 함수로 각자 계산할 수 있다
- 총이 Actor인 이유: 총 종류마다 모양·소켓·데이터가 달라 Pawn을 바꾸지 않고 총만 교체할 수 있고, M2에서 총이 자기 상태(탄약 등)의 동기화 단위가 된다
  - 처음 근거였던 "떨어뜨림·줍기"는 같은 회의에서 "라운드 전 총 선택, 라운드 중 고정"으로 결정되며 사라졌다. 근거를 다시 확인했고 남은 근거로 충분하다고 판단했다

## 결정 2: 입력 소스

### 검토한 대안

| | A. 가짜 트래킹 | **B. 입력 소스 교체형** | C. 외부 시뮬레이터 |
|---|---|---|---|
| 방식 | 데스크톱일 때 MotionController 위치를 코드로 직접 이동 | 입력 소스 클래스가 `FXRInputFrame`을 만들고, 환경에 맞는 소스를 끼움 | Meta XR Simulator 등이 OpenXR 단계에서 흉내 |
| 장점 | 가장 단순 | 녹화·재생 소스 추가가 쉬움, 프레임 구조체가 M2 전송 데이터가 됨 | 코드 불필요 |
| 단점 | 녹화·재생과 테스트가 어려움 | 클래스가 늘어남 | 이 PC에서 사용 불가 (AMD 미지원, Listen Server 크래시 — [ADR-0003](ADR-0003-engine-toolchain-xr.md)) |

### 결정

**B안.** `UXRInputSource`를 부모로 OpenXR / 데스크톱 / (나중) 재생 입력 소스를 둔다.

### 이유

- ADR-0001에서 약속한 녹화·재생 테스트가 클래스 하나 추가로 가능하다
- `FXRInputFrame`이 그대로 M2에서 서버로 보낼 데이터가 되어, M1 구조를 M2에서 재사용한다

## 같은 회의의 관련 결정

| 항목 | 결정 |
|---|---|
| 사격 판정 | 히트스캔. `TraceShot()` 하나로 감싸 탄도 방식으로 교체 가능하게 |
| 양손 파지 진입 | 위치만 (버튼 없음) |
| 경계 깜빡임 | 켜짐 5cm / 꺼짐 7cm 히스테리시스 |
| 주 손이 총을 놓기 | 없음. 라운드 전 선택한 총으로 끝까지 (파밍 없음) |
| 주 손 | `PrimaryHand` 변수, MVP는 오른손 |
| 좌표계 | 모든 포즈는 VROrigin 기준 로컬 |
| 무기 교체 | 백로그. `EquipWeapon()`으로 확장 여지만 둠 |

## 결과 및 주의점

- 클라이언트는 양손 파지 "판정 결과"를 보내지 않는다. 포즈만 보내고 서버가 다시 판정한다 (서버 권위)
- 템플릿의 잡기 시스템은 쓰지 않는다. 총 장착은 `EquipWeapon()`
- 입력 소스 선택이 잘못되면(예: 헤드셋 연결 상태 오판) 원인 파악이 어려우므로, 현재 활성 입력 소스를 디버그 표시에 노출한다
