## 1. 핵심 게임 루프

> 주 손으로 총을 들고 다니다가 적을 발견하면, **누가 더 빠르고 정확하게 보조 손으로 자세를 잡느냐**에 따라 조준이 안정되고 반동이 잡힌다.

이 게임의 실력은 **"빠르고 정확하게 자세를 잡는 능력"** 이다. 설계가 애매할 때는 "이 결정이 자세 잡는 속도와 정확도를 실력으로 만들어 주는가"로 판단한다.

## 2. M1 목표와 완료 기준

M1은 **싱글 플레이**다. 단, M2(네트워크)에서 뜯어고치지 않도록 처음부터 서버 권위 구조를 염두에 두고 만든다.

1. **데스크톱 시뮬레이션**: 에디터 Play에서 키보드·마우스로 머리와 양손을 조작할 수 있다
2. **총 장착**: 시작할 때 선택한 총이 주 손에 Snap 방식으로 붙고, 끝까지 떨어지지 않는다 (M1은 기본 총 하나를 자동 장착, 선택창 UI는 M2 이후)
3. **사격**: 트리거를 당기면 총구에서 히트스캔(라인 트레이스)으로 판정하고, 맞은 지점이 표시된다
4. **양손 파지**: 보조 손이 판정 기준 안에 들어오면 양손 파지 상태가 되고, 총구 방향이 "주 손 → 보조 손"을 따른다
5. **디버그 표시**: Grip/Aim 축, 총열 선, 양손 파지 허용 범위를 켜고 끌 수 있다
6. **Quest 실기 확인**: 같은 동작이 Quest 3S에서도 된다
7. **M2 대비 구조**: 서버로 보낼 트래킹 데이터(머리·양손 포즈)가 한 곳(`FXRInputFrame`)에 모인다

**M1에서 하지 않는 것**: 네트워크, 조준 안정도 계산(M3), 데미지와 HP, 총 선택 UI, 무기 교체

## 3. 클래스 구조

```
AXRFPSPawn (Actor)
 ├─ VROrigin (SceneComponent)                   플레이 공간 바닥 기준점
 │   ├─ Camera                                  머리 (HMD)
 │   ├─ MC_LeftGrip / MC_LeftAim                왼손 포즈 2개 (UMotionControllerComponent)
 │   └─ MC_RightGrip / MC_RightAim              오른손 포즈 2개
 ├─ LeftHand, RightHand (UXRHandComponent ×2)  손 하나의 상태
 ├─ Pose (UXRPoseComponent)                     매 프레임 입력 소스에서 FXRInputFrame을 받아 보관
 ├─ InputSource (UXRInputSource 파생)            실행 환경에 맞는 입력 소스
 └─ Debug (UXRDebugDrawComponent)                디버그 표시

AXRWeapon (Actor)
 ├─ Mesh + 소켓 (Grip, Muzzle, 보조 손 구간)
 ├─ WeaponData (UXRWeaponData, 데이터 에셋)       무기별 기준값
 ├─ EvaluateTwoHandGrip()                        양손 파지 판정 + 총구 방향
 └─ TraceShot()                                  히트스캔 사격 판정
```

클래스 이름은 구현 PR에서 Epic 코딩 표준에 맞춰 확정한다.

### 책임

| 클래스 | 책임 | 하지 않는 것 |
|---|---|---|
| `AXRFPSPawn` | 컴포넌트 조립, `EquipWeapon(총)`, `PrimaryHand` 보관 | 입력 해석, 무기 규칙 |
| `UXRHandComponent` | 손 하나의 상태: 트래킹 유효, 들고 있는 무기 | 잡기·놓기 (총은 자동 장착이라 불필요) |
| `UXRPoseComponent` | 이번 프레임의 `FXRInputFrame` 보관, 다른 컴포넌트에 제공 | 입력이 어디서 왔는지 알 필요 없음 |
| `UXRInputSource` | `FXRInputFrame` 만들기 | 게임 로직 |
| `AXRWeapon` | 무기 규칙 보유, 양손 파지 판정, 사격 판정 | 입력 읽기 |
| `UXRDebugDrawComponent` | 축, 총열 선, 허용 범위 그리기 | 게임 로직 |

설계 원칙: **정보를 가장 잘 아는 쪽에 책임을 준다.** 손 상태는 손에, 무기 규칙은 무기에.

### 주 손

- `PrimaryHand` 변수로 둔다. MVP는 **오른손 고정**
- 코드 어디에서도 "오른손이면"으로 하드코딩하지 않고 `PrimaryHand`를 본다 → 나중에 왼손잡이 지원은 설정값 변경만으로 가능

### 총 장착

- 총은 라운드 시작 시 `EquipWeapon(총)`으로 주 손 Grip에 **Snap 장착**되고, 라운드 동안 떨어지지 않는다
- 템플릿의 잡기 시스템(가까운 물건 찾기, Try Grab, 넘겨잡기)은 **사용하지 않는다**
- 무기 교체는 백로그. 나중에 넣을 때도 `EquipWeapon`을 재사용한다

## 4. 입력 데이터: `FXRInputFrame`

Quest든 키보드든 매 프레임 이 구조체 하나를 만든다. 뒤쪽 코드는 입력이 어디서 왔는지 모른다.

| 항목 | 타입 | M2 서버 전송 | 용도 |
|---|---|---|---|
| 프레임 번호 / 시각 | 정수, 시간 | ✅ | 순서 보장, 지연 보정 |
| 머리 포즈 | `FTransform` | ✅ | 자세 판정, 머리-손 거리 검증 |
| 왼손·오른손 Grip 포즈 | `FTransform` ×2 | ✅ | 총구 계산, 양손 파지 판정 |
| 왼손·오른손 Aim 포즈 | `FTransform` ×2 | ❌ | UI 전용 (로컬) |
| 트래킹 유효 (머리, 왼손, 오른손) | `bool` ×3 | ✅ | 끊긴 구간을 안정도·치트 검증에서 제외 |
| 헤드셋 착용 | `bool` | ✅ | 벗으면 자리 비움 |
| 트리거 (주 손) | `float` 0~1 | ✅ | 사격 |
| 이동 스틱 (보조 손) | `FVector2D` | ✅ | 스틱 연속 이동 |

- 모든 포즈는 **VROrigin 기준 로컬 좌표**. 서버는 Pawn 위치와 합쳐 월드 좌표를 계산한다
- 보조 손 그립 버튼은 없다. 양손 파지는 위치만으로 판정한다 (6장)

## 5. 입력 소스

```
UXRInputSource                  "FXRInputFrame을 만들어라"
 ├─ UXROpenXRInputSource         Quest: MotionController 컴포넌트 + Enhanced Input
 ├─ UXRDesktopInputSource        키보드·마우스로 머리·양손 흉내
 └─ (나중) UXRReplayInputSource   녹화한 프레임 재생 → 서버 검증 테스트
```

- 선택 규칙: 헤드셋이 연결되어 OpenXR가 활성이면 OpenXR, 아니면 데스크톱. 콘솔 명령으로 강제 전환 가능
- 데스크톱 조작 (초안, 구현 시 조정)
  - 마우스: 머리 회전
  - 숫자 키: 손 자세 프리셋 (예: 1 = 한 손 들기, 2 = 양손 파지 자세)
  - 손 미세 조정 키: 보조 손을 총열 기준 앞뒤·위아래로 이동 (판정 경계 테스트용)
  - 좌클릭: 트리거

## 6. 양손 파지 판정

### 역할 분담

| 역할 | 담당 |
|---|---|
| 재료 제공: 주 손·보조 손 Grip 포즈, 트래킹 유효 | Pawn (`FXRInputFrame`) |
| 규칙 보유: 총열 선, 허용 거리, 구간 | 총 (`UXRWeaponData`) |
| 판정: 재료 + 규칙 + 이전 상태 → 양손 파지 여부, 총구 방향 | 총의 함수 `EvaluateTwoHandGrip()` |

- 판정 함수는 **입력이 같으면 어디서 돌려도 같은 결과**를 낸다
- 클라이언트: 즉시 계산해 진동·연출에 사용
- 서버(M2): 클라이언트가 보낸 **포즈로 다시 계산**해 탄 퍼짐 등 결과에 사용. 다르면 서버가 이긴다
- 클라이언트는 판정 결과("나 양손 파지 중")를 보내지 않는다

### 판정 기준 (초기값, 무기 데이터에 저장, 플레이테스트로 조정)

| 기준 | 켜질 때 | 꺼질 때 |
|---|---|---|
| 보조 손 Grip과 총열 선 사이 수직 거리 | 5cm 이내 | 7cm 밖 |
| 두 손 사이 거리 | 20~30cm | (구현 시 결정) |
| 총 로컬 좌표 앞뒤 관계 | `보조손.X > 주손.X` | 같음 |
| 보조 손 트래킹 유효 | 필요 | 끊기면 즉시 해제 |

- **진입 조건은 위치만** (버튼 없음): 핵심 게임 루프의 "빠르게 자세 잡기"와 일관
- **켜짐/꺼짐 기준을 두 개로**(히스테리시스): 경계에서 상태가 깜빡이는 것을 방지
- 양손 파지 중 총구 방향 = 주 손 Grip → 보조 손 Grip 방향

## 7. 사격

- **히트스캔**: 총구 소켓 위치·방향에서 라인 트레이스, 처음 닿은 물체가 맞음
- `TraceShot(총구 Transform)` 함수 하나로 감싼다 → 나중에 탄도 방식으로 바꿀 때 함수 안만 수정
- 판정과 연출 분리: 예광탄·총구 화염·탄흔은 판정과 무관한 연출

## 8. 실행 위치 원칙

| 종류 | 위치 |
|---|---|
| 게임 결과 (명중, HP, 양손 파지의 효과) | 서버 (M2부터) |
| 느낌과 연출 (잡기·발사 진동, 이펙트) | 클라이언트 즉시 |
| 결과 확인 연출 ("맞혔다" 진동) | 서버 판정을 받은 뒤 |

## 9. 구현 순서 (PR 단위)

| # | 내용 | 확인 방법 |
|---|---|---|
| 1 | `FXRInputFrame`, `UXRInputSource`, 데스크톱 입력 소스, Pose 컴포넌트 | 에디터 Play에서 디버그 축이 키보드·마우스대로 움직임 |
| 2 | Pawn 컴포넌트 트리, Hand 컴포넌트, `PrimaryHand` | 머리·양손 위치에 디버그 표시 |
| 3 | `AXRWeapon`, 무기 데이터, `EquipWeapon` Snap 장착 | 총이 주 손에 붙어 따라감 |
| 4 | 히트스캔 사격, 명중 지점 표시 | 클릭하면 총구에서 선이 나가고 맞은 곳 표시 |
| 5 | 양손 파지 판정, 히스테리시스, 디버그 표시 | 보조 손 프리셋·미세 조정으로 켜짐/꺼짐 경계 확인 |
| 6 | OpenXR 입력 소스, Quest 실기 확인 | Quest에서 1~5 동작 (M0 단계 5·7·8 완료 후) |

코드 분담(팀장 구조·예시 → 신입 확장)은 각 PR 시작 시 정한다.

## 10. 남은 결정 / 백로그

- 이동 방식: 스틱 연속 이동 + 멀미 완화 옵션 (M1 후반 또는 M2)
- 양손 파지 진입 직후 안정되기까지의 시간 (M3 조준 안정도 설계에서)
- 무기 교체, 왼손잡이 설정, 탄도 방식 등 → [백로그](../backlog.md)
